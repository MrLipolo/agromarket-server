## Безопасность

- **Заголовки и ограничение тела запроса:** подключён `helmet()` (скрывает `X-Powered-By`, добавляет защитные HTTP-заголовки `X-Content-Type-Options`, `Strict-Transport-Security` и др.) и лимит размера JSON `express.json({ limit: '100kb' })`.
- **CORS:** разрешены запросы только с доверенных доменов (`https://agromarket-mrlipolo.vercel.app`, `http://localhost:5173`) через переменную окружения `CORS_ORIGINS` / `CORS_ORIGIN`.
- **Rate limit:** на `/api/auth/login` и `/api/auth/register` установлено ограничение `10 попыток за 15 минут` с одного IP (`express-rate-limit`, `trust proxy = 1` для корректной работы за балансировщиком Render, отключение лимитера при `NODE_ENV=test`).
- **Валидация входных данных (`zod`):** проверка тела запроса для регистрации (`registerSchema`), входа (`loginSchema`), создания и обновления товара (`productSchema`, `productUpdateSchema`), защита от mass assignment (отбрасывание лишних полей, включая `role`) и проверка целочисленного положительного параметра `:id` (`idParam`).

### Ответы на контрольные вопросы

- **`npm audit`: что нашли, что исправили, что оставили и почему:** при проверке `npm audit` обнаружены 3 уязвимости (2 moderate, 1 high) в пакетах разработки (`devDependencies`), которые не попадают на продакшен-сервер (`npm audit --omit=dev` — 0 уязвимостей). Критичные зависимости без ломающих изменений обновлены, пакеты из `devDependencies` оставлены без `--force`, чтобы не нарушить совместимость тестового окружения Vitest.
- **Были ли секреты в истории git:** нет, проверка `git log --all -p` и `git ls-files` подтвердила, что `.env` не попадал в коммиты, а `DATABASE_URL` и `JWT_SECRET` задаются исключительно через переменные окружения.
- **Был ли возможен mass assignment (`role: admin`) до валидации:** да, при передаче дополнительного поля `"role": "admin"` в `POST /api/auth/register` оно могло быть обработано сервером. После внедрения `zod` (`registerSchema`) все поля, не описанные в схеме, автоматически отбрасываются до передачи в контроллер, поэтому назначается только роль по умолчанию (`buyer`).
- **Зачем `trust proxy` на Render:** Render пропускает весь входящий трафик через обратный прокси-балансировщик. Без `app.set('trust proxy', 1)` Express видит для всех клиентов один и тот же IP-адрес балансировщика, и блокировка после 10 неудачных попыток входа срабатывала бы одновременно для всех пользователей сервиса.
- **Почему проверки в React-форме недостаточно:** валидация во фронтенде выполняется в браузере пользователя и нужна только для удобства интерфейса. Любой злоумышленник может обойти форму и отправить HTTP-запрос напрямую на API через `curl`, Postman или PowerShell с отрицательной ценой, огромным телом или подменёнными полями.
- **Время отката на Vercel и зачем нужен `git revert`:** откат через `Instant Rollback` на Vercel занял **2 с**. Одного отката на Vercel недостаточно, так как он лишь переключает активную сборку на предыдущий снимок на стороне хостинга, оставляя сломанный коммит в ветке `main` на GitHub — без `git revert` при следующем деплое ошибка снова попадёт в продакшен.
- **Использовал(а) ли ИИ и для чего:** да, ИИ использовался для сверки настроек `helmet`, `cors` и `express-rate-limit`, составления схем валидации `zod` и тестовых сценариев Supertest, а также диагностики деплоя; вся функциональность проверена автотестами и ручными запросами к продакшен-API.
